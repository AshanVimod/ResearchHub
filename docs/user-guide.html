Important folders

  • <app folder>\: the app itself
  • <app folder>\data\: all your data
  • <app folder>\backups\: backup zips (default)

Three rules worth remembering

  • Never delete the data folder: it is your work.
  • Point the backup folder at OneDrive or Google Drive so a copy leaves the laptop.
  • Quit the app before restoring a backup or editing research.db.

2Installing (first time)

You need a Windows computer and an internet connection for the first setup only. After that the app works offline.

Step 1: install Python

  1. Go to https://www.python.org/downloads/ and download Python 3.11 or newer (tested with 3.13).
  2. Run the installer. On the first screen, tick "Add python.exe to PATH", then click Install Now.

Step 2: get the code

Option A (easiest), download a ZIP:

  1. Open https://github.com/AshanVimod/ResearchHub, click the green Code button, then Download ZIP.
  2. Right-click the downloaded file → Extract All…. Move the extracted folder somewhere permanent and give it a short name, for example C:\ResearchHub.

Option B, with Git (makes updating easy later):

git clone https://github.com/AshanVimod/ResearchHub.git C:\ResearchHub
Tip. Avoid a path with special characters, and don't run it from inside the ZIP file. A folder under OneDrive works, but a plain folder such as C:\ResearchHub is simplest.

Step 3: run start.bat once

  1. Open the app folder and double-click start.bat. If Windows shows "Windows protected your PC", click More info → Run anyway.
  2. A black window shows progress. It creates a private Python environment (.venv) and installs the required packages; this takes a few minutes.
  3. It then puts a Research Hub shortcut (amber "R" icon) on your desktop and opens the app in your browser.

From now on, just double-click the desktop shortcut. You never need start.bat again unless you move the folder or delete .venv.

Step 4 (optional): explore the demo

Double-click demo.bat to open a separate copy filled with a made-up project ("Forecasting Urban Air Quality with Low-Cost Sensors"): references, diary entries, tasks, logged hours, labels, experiment runs, viva questions and a small sample research folder. It runs on http://127.0.0.1:8010 and stores everything in sample-data\, so your real data is never touched. Delete the sample-data folder to reset it. Quit it from its own Settings page.

3Starting and stopping

The normal way: the desktop shortcut

  1. Double-click Research Hub on your desktop.
  2. If the app is not running, it starts silently in the background. There is no console window to keep open.
  3. Your browser opens at http://127.0.0.1:8000. If the app was already running, you just get a new tab.

You can right-click the shortcut and choose Pin to taskbar or Pin to Start. If something is wrong, the shortcut shows a Windows message box (for example "run start.bat first" when the Python environment is missing).

Stopping the app

  • Settings → Your data → Quit Research Hub, then confirm. A "Research Hub has stopped" page appears.
  • Signing out of Windows or shutting down also stops it. Nothing is lost, because everything is already saved.
  • Closing the browser tab leaves the app running quietly in the background (very little memory or CPU).

Recreating the shortcut

If the shortcut is deleted, or you moved the app folder, run start.bat again, or in PowerShell:

powershell -ExecutionPolicy Bypass -File "C:\ResearchHub\scripts\make_shortcut.ps1"

Add -Folder "D:\Somewhere" to put the shortcut in another folder.

Start automatically when Windows starts (optional)

Press Win+R, type shell:startup, press Enter, and copy the shortcut into that folder.

Starting by hand (for troubleshooting)

cd C:\ResearchHub
.venv\Scripts\python app.py

Error messages then appear in the window. Stop with Ctrl+C.

What happens on every start-up. The app applies any pending database updates, makes an automatic backup if the last one is more than 24 hours old, imports experiment runs queued while it was closed, and about 10 seconds later scans your research folders for new or changed files (then every 30 minutes).

4Setting up your project

On the very first start the app opens the Welcome page. Only the project start date is required: week numbers ("Week 9 of 34"), the current phase and all milestone dates are calculated from it. Fill in your title, name and supervisor too, then press Start. Everything can be changed later on the Settings page. Settings are stored in the database, not in a file.

Milestones

The Milestones panel on Settings lists a typical 34-week final-year plan (outline, proposal defence, mid-term review, draft and final thesis, viva, diary, optional IEEE paper) with week ranges and marks weights. Dates follow the start date automatically. When your coordinator announces a real date, type it in and press Save: it becomes Overridden and stays fixed. Reset makes it follow the start date again. Each milestone also has a status.

5Features, page by page

The top bar on every page has the search box, quick capture, the work timer and the light/dark theme switch.

Overview

Dashboard

  • "Week N of 34", the current phase and a 34-week timeline with every milestone.
  • Alerts: no supervisor meeting for too long, behind pace on signed meetings, diary entries older than 7 days still unsigned, overdue tasks.
  • Next deadline, today's tasks and hours logged toward your target.

Calendar

  • Month, week and list views of milestones, meetings and task due dates. Drag a task to change its due date.

Supervision

Diary supervisor meeting record

  • One entry per meeting: date, mode, attendees, agenda, discussion, decisions, feedback, reflection and action items.
  • Each action row becomes a task automatically (saving again never duplicates). Mark entries as signed; link references and files.
  • Export one entry, or a whole semester as a Word file with a cover page and one meeting per page.

Tasks Kanban board

  • Columns To do, Doing, Done. Drag cards between columns; Done stamps the completion date. Due dates, priorities, thesis chapter.

Time hours log

  • Timer in the top bar (Alt+T) with categories: reading, coding, data, writing, meeting, experiments, presentation, admin. Add or correct entries by hand. A timer left running over 12 hours asks for the real end time. Summary per category and week.

Literature

References your library

  • Add by DOI (Crossref), arXiv ID, PDF upload (the DOI is read from its first pages), BibTeX import (Zotero, Mendeley, Google Scholar), or by hand. Offline, the form still opens for typing.
  • Duplicates are caught: the same DOI is blocked; a near-identical title offers a merge.
  • Reading status, 1–5 rating, chapters, notes, and highlights in the built-in PDF viewer.
  • Bibliography: IEEE-formatted, exported to Word or .bib.

Matrix literature matrix

  • Spreadsheet view of every reference: country, dataset, sample, label source, method, metrics, key result, limitations, relevance. Click a cell to edit (Enter saves, Esc cancels). Choose columns. Export CSV or Excel.

Files read-only index of your research folders

  • Every file with type, size, pages and tags. Open / Show in Explorer. PDFs open in the built-in viewer. Duplicates page groups identical files (the app never deletes anything). Recent changes, Re-scan now, and Make reference from a PDF.

Search everything in one place

  • Files (including PDF text page by page), references, notes, diary, tasks, inbox, experiments and labels, with highlighted snippets. Save frequent searches. Optional Meaning mode (section 8).

Writing & research

Thesis chapter tracker

  • Chapters with status and target/actual word counts read from your thesis .docx (it reads a copy if Word has it open), abstract-length badge, word-count history chart, supervisor comments per chapter, and editable submission checklists.

Labels dataset label tracker

  • For projects that build a labelled dataset: one row per entity × period × evidence source (primary record, published source, expert judgement, rule, survey, other), with label 0/1, evidence strength, evidence link or file, "doubtful" and "reviewed with supervisor" flags. An entity-period is positive if any row is positive. Versioned labelling rules. CSV export. Ignore this page if your project doesn't need it.

Experiments ML run log

  • Runs with approach (baseline, proposed, ablation, tuning, transfer, other), model, data version, split, parameters and metrics. Star the best, compare runs side by side. Log straight from Jupyter (section 8).

Viva presentation practice

  • Slide checklist; practice timer for a 15-minute talk plus 5 minutes of questions (amber at two minutes left, red overtime); practice-run history; question bank with prepared answers and confidence; Drill mode asks your shakiest questions first.

You

Inbox quick capture

  • Everything captured with Alt+N. Turn each item into a task, a reference note or a meeting agenda point, or archive it.

Settings

  • Configuration (section 4), milestones, backup (section 7), Your data (section 6) and About (credits and contact).

6Your data: where it is saved

Everything saves instantly, and stays on your computer. There is no Save-all step and no cloud account. When you press Save, tick a box, drag a card or stop the timer, the change is written to the database straight away.
Location (inside the app folder)Contents
data\research.dbEverything you type: settings, milestones, diary, tasks, time, references, notes, highlights, matrix, file index, thesis, labels, experiments, viva questions, inbox, saved searches. One SQLite file. research.db-wal and -shm next to it belong to it.
data\library\PDFs you upload on the References page (copies).
data\exports\Every Word, CSV, Excel and .bib file you export.
data\models\The semantic-search model, once downloaded (about 90 MB).
data\app.log, data\server.logLogs for troubleshooting.
data\secret_keyRandom key that protects forms. Recreated if lost; don't share it.
backups\ (or your backup folder)Daily and manual backup zips.
experiments_pending.jsonlRuns logged from Jupyter while the app was closed; imported on next start.

Your browserOnly view preferences: light/dark theme, last timer category, chosen matrix columns.

Your research folders are only ever read: the app never changes, moves or deletes your files. The data and backups folders are excluded from Git, so your work is never uploaded to GitHub.

How to look at your data

  1. Inside the app: Settings → Your data shows each location with its size, how many records of each kind you have, and an Open data folder button.
  2. As ordinary files: use the export buttons (Diary → Word, Matrix → Excel/CSV, Bibliography → Word/.bib, Labels → CSV).
  3. The raw tables: install the free DB Browser for SQLite (sqlitebrowser.org), choose Open Database Read Only → data\research.db, then the Browse Data tab.

7Backup and restore

Backups

  • Automatic: on every start-up, if the last backup is more than 24 hours old.
  • Manual: Settings → Backup → Back up now.
  • Each backup is a zip named researchhub_YYYYMMDD_HHMM.zip containing research.db and library\. The newest Backups to keep (default 10) are kept.
  • Recommended: set Backup folder to a folder inside OneDrive or Google Drive so a copy survives a lost or broken laptop.

Restoring a backup

  1. Stop the app: Settings → Your data → Quit Research Hub.
  2. Copy the current data folder somewhere safe, just in case.
  3. Unzip the chosen backup over data\, replacing research.db and library\.
  4. Delete any research.db-wal and research.db-shm files left beside it.
  5. Start the app again with the shortcut.

Moving to a new laptop

  1. Install Python (section 2, step 1).
  2. Copy the whole app folder (you can leave out .venv and sample-data).
  3. Double-click start.bat; it rebuilds .venv and makes a new desktop shortcut.
  4. Update Research folders, Thesis .docx path and Backup folder in Settings if the paths changed.

Updating to a newer version

With Git: git pull in the app folder, then run start.bat. With a ZIP: download the new ZIP, extract it, and copy your old data folder into the new app folder before running start.bat. Database updates are applied automatically on start.

8Jupyter logging and semantic search

Logging experiment runs from Jupyter

import sys; sys.path.append(r"C:\ResearchHub\scripts")
from log_experiment import log_run
log_run(run_name="rf_baseline_v1", approach="baseline", model="RandomForest",
        params={"n_estimators": 200}, metrics={"accuracy": 0.86, "f1": 0.81})
  • approach is one of baseline, proposed, ablation, tuning, transfer, other. Metrics must be numbers.
  • If the app is not running, the run is saved to experiments_pending.jsonl and imported on the next start.
  • The helper posts JSON to http://127.0.0.1:8000/api/experiments; any program on your computer can do the same.

Semantic ("Meaning") search: optional

Keyword search finds exact words; Meaning search finds passages about an idea even when the wording differs.

  1. Install the extra packages once (a large download, mostly PyTorch): 
    cd C:\ResearchHub
.venv\Scripts\pip install -r requirements-semantic.txt
  2. Settings → Integrations → switch on Semantic search → Save.
  3. The next scan downloads the all-MiniLM-L6-v2 model (about 90 MB) into data\models and processes your files in the background (about 5 minutes for 140 papers). After that it works offline.
  4. The Search page gets a Keyword / Meaning toggle.

Internet use

The app works fully offline except for DOI lookups (Crossref), arXiv lookups, and the one-time installs above.

Python · Flask 3.1 served by waitress · SQLite (WAL mode, foreign keys, FTS5 full-text search) · PyMuPDF · python-docx and openpyxl · Bootstrap 5.3, HTMX 2, Alpine 3, FullCalendar, SortableJS, Chart.js and PDF.js, all stored locally in static\vendor. Exact versions are pinned in requirements.txt.

Security and privacy

The app listens on 127.0.0.1 only, so other computers on the network cannot reach it, and there is no login because only you can open it. Forms are protected against cross-site requests, SQL is parameterised, and file paths are checked to stay inside your configured folders. Nothing you enter is sent anywhere.
